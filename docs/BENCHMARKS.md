# Slideshow, quantified

- **Measured 15 October 2026**, not estimated from GPU specifications. The sanitized [samples](benchmarks.json) and [chart script](../tools/plot_benchmarks.py) are included. The screenshot is a real screen-on phone capture, resized for this page.
- **Phone:** Motorola Edge 50 Ultra, SM8635 / Adreno 735; Android Vulkan compatibility path. **PC:** NVIDIA GeForce RTX 5080, Windows, portable Phoenix Vulkan provider. Phoenix source: `4c9b75ff42b6945352f66f309dc84404e498f4cf` / SDK 0.8.1-beta.
- Matching headless workload: the same RGB32F image and signed motion planes, 320×144 input, 320×320 internal canvas, one pass, `[1,1,1,1,1,1,1,1]` block repetitions, reset history and identical controls/model. Input, motion and model SHA-256 values are in the JSON. Private inputs are not redistributed.
- Metric: complete synchronous host-plane **C API frame-call milliseconds**, including transfers, preparation and resolve. Excludes session creation, reading files, drawing the museum and presenting its frame. Each process makes seven calls; the first is excluded from the six-sample warm median. Cold calls are retained separately in JSON.
- Phone baseline → optimized: **2,009.68 → 1,247.08 ms**, **1.61× faster**. GPU submission-span medians: **1,882.33 → 1,101.17 ms**. These runs and CPU-identical output are also documented in [Phoenix's mobile validation](https://github.com/RazvanManolache/dlss5-phoenix-addon/blob/4c9b75ff42b6945352f66f309dc84404e498f4cf/docs/VULKAN_MOBILE_2026-10-15.md).
- Fresh PC run: **77.18 ms** median warm complete call. Compatibility is opted in on both devices; actual shader selection is device-dependent. RTX uses the desktop 32×32 fallback, not the phone's integer-half workgroup kernels. This compares this workload on two machines, not isolated hardware throughput or identical instruction streams.
- Output on baseline phone, optimized phone, PC and CPU reference has SHA-256 `8c6bb14d3e2198dadf68f314ba44afd1a52a633d5f4bba582d338c6f020d6eee`. This verifies this fixture, not every image or control setting.
- The phone's **screen-on app** is a separate measurement: eight completed calls, median **1,464.12 ms**, reported completed-model rate **0.655 FPS**, display rate **12.236 FPS**. Frozen 320×144 comparison; proof-file writing disabled while timing. Actual GL/compositor pixel checks verified that the processed side contained the saved Phoenix result.
- Rendering uses native display dimensions; the matched comparison deliberately shows both sides at the small processing resolution. That is why the screenshot is soft. Bilinear enlargement is not additional model inference.
- No sustained thermal test, randomized repetitions or animated-game FPS claim. Phone runs were serial; scheduling, clocks and temperature vary. Profiling submission spans differ by backend. Chart dots show every warm sample; they are not confidence intervals. Calls/second in the README is `1000 / median call ms`.
- The PC can do substantially better with its native RTX path: Phoenix separately measured **4.262 ms complete D3D12 texture evaluation at 1080p**. Different API, execution path and workload boundary: deliberately excluded from the phone ratio. See [native validation](https://github.com/RazvanManolache/dlss5-phoenix-addon/blob/4c9b75ff42b6945352f66f309dc84404e498f4cf/docs/NATIVE_LIBRARY_VALIDATION_2026-10-15.md).

## Reproduce

- With your own copies of the matching private inputs/model and a built or released Phoenix SDK, run `python tools/benchmark.py --help`. It runs seven calls and writes sanitized timing samples and input/output hashes; it fails if the output differs from a supplied reference hash.
- An arbitrary image is a different fixture. Do not present its timing as a rerun of the published samples. Device selection is explicit; use Phoenix's `phoenix_frame --vulkan-devices RUNTIME_FOLDER` to list devices.
- Install `requirements.txt`, then run `python tools/plot_benchmarks.py` to regenerate both charts directly from the included JSON.
